## 保留的已知失败

前端 3 项已经在原开发仓库独立复现：

- 拆单父单业务过滤的源码约束检查。
- 正常导航读取罚款缓存的调度断言。

本地 API 的 12 项原有失败也已在原仓库用同一组隔离测试复现：4 项账号归属源码/锚点约束、2 项拆单关系、4 项订单同步/回读、2 项退货同步。它们不能被“公开版改了目录”解释为已修好。

另外 4 项真实 SKU 证据检查需要未公开的生产采集证据与 SQLite proof 文件。本仓库刻意不包含这些真实资料；原检查仍然存在，缺少证据会失败。不能用合成数据冒充真实平台验收，也不能把门禁改成跳过。

GitHub CI 运行真实测试，因此相关 job 可能为红色。这是已知问题的公开记录，不应通过删除失败测试、批量允许失败或放宽门槛变成虚假的全绿。

## 运行限制

- 自部署目前以 Windows 源码启动为入口，需按文档安装 Node、Python 及 .NET SDK。
- 官方发行服务、收费模型/OSS、微信及跨境企业接口不随源码附赠；需配置自己的访问权限。
- 本地 CA 和配置有有效期；自动续期、跨机器恢复及生产多实例部署尚未完成验收。
- 全局结构门禁、长时间运行与真实平台变体不能由本次源码和授权链路检查代替。
- npm 锁文件清单不等于全部二进制依赖 SBOM；自行分发安装包时仍需补齐对应许可义务。

欢迎优先贡献可复现的隔离测试、这些失败的修复以及部署文档改进。涉及利润、费用、汇率和账号归属时，必须保留原口径并说明证据。
