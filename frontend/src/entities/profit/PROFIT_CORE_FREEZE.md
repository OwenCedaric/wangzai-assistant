## 冻结边界

- 利润台账公式、实际/预估利润结果状态
- Ozon 财务流水归集、拆单匹配和去重
- 售后分类、退款、补偿和罚款归集
- 汇率和费用换算
- 财务状态不可降级规则
- 精确跨境流水来源、证据和真实 0 不可被低优先级页面重建覆盖
- 日期选择后先按当前范围读取 SQLite，再只同步当前选中店铺；禁止恢复全店铺拥堵刷新
- 订单数量以 `shop_id + posting_number` 和明确拆单关系为准；禁止恢复按金额/数量相等猜父单的算法
- 利润订单与利润台账只走 SQLite；禁止恢复旧 JSON 大快照、旧 JSON 台账回退或本地财务孤立快照
- 远程订单/财务刷新不得阻塞本地商品摘要补全和新账本落盘；商品补全必须同时检查图片、预估佣金与材积，并保持店铺隔离和精确 SKU 兜底

页面、组件、请求服务和新证据源适配器允许拆分，但只能向冻结核心提供规范化证据，不能自行计算或覆盖利润结果。

## 变更门槛

禁止直接修改冻结文件后更新哈希。计算文件变化必须升级计算版本；仅页面读取、日期或缓存运行时变化也必须升级运行时版本。确需调整时必须同时完成：

1. 新建明确的规则变更记录。
2. 升级 `PROFIT_LEDGER_CALCULATION_VERSION`。
3. 补充对应回归测试和真实订单样本。
4. 重建全量利润快照并核对订单总数、拆单、待确认、盈利和亏损。
5. 全量 `npm run check` 通过后，才能更新冻结清单哈希和数据基线。

跨境巴士账单等后续能力应放在独立 `services/` 适配层。接入真实账单属于新证据源，不得在页面或适配器内另建第二套利润公式。

## 已永久删除的旧路径

- `profitLegacyPipelineFreeze.js`：旧方案不再以“冻结开关”保留，避免后续误恢复。
- `profitLocalSnapshot.js`：利润订单旧 JSON 大快照生成器已删除。
- `filterProfitSplitAggregateRows`：按金额/数量相等推测父单的算法已删除，拆单只认持久化关系。
- `requestOzonProfitLegacyLocalOnlySnapshotForShops`：缺售后/完整财务证据的孤立利润快照已删除。
- `allowLegacyLocalSnapshot`：售后页旧本地快照回退开关已删除。

冻结守卫同时检查文件哈希、已退役文件不存在、已退役符号不得回归；旧代码不是“暂时不用”，而是禁止恢复。
