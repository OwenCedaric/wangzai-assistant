# 开发工作流

## 定位与实施

先明确用户可观察的问题、保持不变的行为和验收方式，再沿入口、调用方、持久化与回读定位根因。用 `rg` 定向查代码和测试，不反复全库扫描或整份读取大日志。保留用户已有改动，不假定存在 Git 或干净工作树。小改动直接做；长任务只保留一份进度/证据/断点记录，接续时不重头规划。

## 验证

先复现再修复；无法复现就说明。按风险选择能证明行为的检查：

| 改动 | 证据 |
| --- | --- |
| 文档、技能 | 引用/元数据有效，相关消费者契约测试 |
| 逻辑、计算 | 正常、缺失、边界与失败分支的定向测试 |
| 页面、性能 | 组件测试加隔离运行证据，记录版本、数据量和耗时 |
| 存储、IPC、浏览器、插件 | 隔离集成：目标归属、取消/失败、落盘回读，必要时重启 |
| 安装、升级、发布 | 实际隔离产物与发布门禁要求的证据 |

静态检查和构建不能证明操作流畅。使用后台/隔离入口，不抢占鼠标或焦点；没有条件就标注未验证。性能对比须环境、版本、样本可比，小样本不外推几十万订单。相关检查通过后，只因新改动、失败或未解疑点扩大或重跑；不为小文案添加逐字复述测试，历史失败单列。

## 入口与交付

根目录没有统一 npm 包；核实子项目 `package.json` 中脚本及副作用。

- 前端定向测试：在 `frontend/` 执行 `npm exec --no -- vitest run <测试文件>`；按需运行 `typecheck`、`build`。
- Node 定向测试：根目录执行 `node --test <测试文件>`。
- 已迁入的冻结细则见 [冻结契约](../references/frozen-contracts.md)；其他冻结入口按 `frontend/package.json` 的 `check:*freeze` 选择，共用链路覆盖受影响模块。
- 发布状态：`node tools/release-readiness.mjs --check`。

`frontend check` 是全量检查；`desktop dev` 会启动应用，`pack/dist` 会构建、封签和打包，不是小改动的默认测试。清理、迁移、安装及更新运行时先核实目标和授权。

交付说明改动、业务逻辑是否变化、实测结果及剩余问题，区分“源码已改”“隔离通过”“运行版本已更新”“真实业务已验收”。

## 成本与并行

默认主代理完成。仅委派可独立交付、确实省时或补足核验的子任务；先开一个，给出边界和完成条件，不层层派生或重复扫描。独立只读检查可并行，重叠写入不并行。节省 token 靠减少重复读取、无关输出和无效往返，不省必要验证；沿用当前模型与推理档位。
